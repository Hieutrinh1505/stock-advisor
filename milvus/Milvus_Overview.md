# Milvus Vector Database Overview for Stock RAG System

## Introduction

### What is Milvus?
Milvus is a high-performance, cloud-native vector database designed for scalable similarity search and AI applications. It's purpose-built for storing, indexing, and querying high-dimensional vectors generated by machine learning models.

### Why Milvus for Stock Recommendations?
For a stock advisor RAG system that recommends stocks based on:
- **Price movements** (historical OHLCV data)
- **News sentiment** (articles, press releases, earnings calls)
- **Historical performance** (technical indicators, fundamental metrics)

Milvus provides:
- **Fast similarity search** across millions of stock data embeddings
- **Metadata filtering** to narrow searches by date, symbol, sector
- **Scalability** to handle growing datasets (years of historical data)
- **Hybrid search** combining semantic search with traditional filters

## 1. Collections & Schema Design

### What are Collections?
Collections in Milvus are similar to tables in SQL databases. Each collection has a schema that defines:
- Primary key field
- Vector field(s) with specified dimensions
- Metadata fields (scalar fields)

### Stock Knowledge Collection Schema

```python
from pymilvus import CollectionSchema, FieldSchema, DataType

# Define fields
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="symbol", dtype=DataType.VARCHAR, max_length=10),
    FieldSchema(name="date", dtype=DataType.INT64),  # Unix timestamp
    FieldSchema(name="content", dtype=DataType.VARCHAR, max_length=5000),
    FieldSchema(name="content_type", dtype=DataType.VARCHAR, max_length=50),  # 'price_action', 'news', 'fundamental'
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=384),  # sentence-transformers dimension
    FieldSchema(name="metadata", dtype=DataType.JSON)  # Additional metadata
]

# Create schema
schema = CollectionSchema(
    fields=fields,
    description="Stock knowledge base for RAG",
    enable_dynamic_field=True
)
```

### Field Explanations

| Field | Type | Purpose |
|-------|------|---------|
| `id` | INT64 | Primary key, auto-generated |
| `symbol` | VARCHAR | Stock ticker (e.g., "AAPL", "GOOGL") |
| `date` | INT64 | Timestamp for time-based filtering |
| `content` | VARCHAR | Original text (price summary, news, etc.) |
| `content_type` | VARCHAR | Categorize data source type |
| `embedding` | FLOAT_VECTOR | 384-dim vector from sentence-transformers |
| `metadata` | JSON | Flexible field for additional info (sector, price, volume) |

## 2. Indexing Strategies

### Index Types Comparison

| Index Type | Build Time | Memory Usage | Query Speed | Use Case |
|------------|------------|--------------|-------------|----------|
| **FLAT** | Fast | Low | Slow (brute-force) | Small datasets (<10K) |
| **IVF_FLAT** | Medium | Medium | Medium | Balanced accuracy/speed |
| **HNSW** | Slow | High | **Very Fast** | Large datasets (>100K) |

### HNSW vs IVF_FLAT for Stock Data

**HNSW (Hierarchical Navigable Small World)**
-  Significantly faster retrieval than IVF_FLAT
-  Lower latency for real-time queries
-  High recall (0.884-1.0 in benchmarks)
- L Higher memory consumption
- **Recommended for**: Production stock RAG with >100K embeddings

**IVF_FLAT (Inverted File with Flat Compression)**
-  No compression, maintains accuracy
-  Lower memory usage
- L Query time increases with dataset size
- L Slower than HNSW
- **Recommended for**: Testing/POC with <100K embeddings

### Creating HNSW Index

```python
from pymilvus import Collection

collection = Collection("stock_knowledge")

# Create HNSW index on vector field
index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",  # Use cosine similarity
    "params": {
        "M": 16,  # Number of bi-directional links (higher = better accuracy, more memory)
        "efConstruction": 200  # Size of dynamic candidate list (higher = better quality, slower build)
    }
}

collection.create_index(
    field_name="embedding",
    index_params=index_params
)
```

### Index Parameter Tuning

- **M (default: 16)**: Higher values (32-64) improve accuracy but increase memory ~2x
- **efConstruction (default: 200)**: Higher values (400-500) improve build quality but slower indexing
- **ef (search time)**: Higher values (64-512) improve recall but slower queries

For stock data: Start with M=16, efConstruction=200, ef=100

## 3. Data Organization with Partitions

### Why Partitions for Stock Data?
Partitions organize data into logical groups, reducing the search scope for time-based queries.

**Example**: Querying "recent AAPL news" only searches the last month's partition instead of all historical data.

### Time-Based Partitioning Strategy

```python
from pymilvus import Collection, Partition

collection = Collection("stock_knowledge")

# Create monthly partitions
partition_2024_10 = Partition(collection, name="2024_10")
partition_2024_11 = Partition(collection, name="2024_11")
partition_2024_12 = Partition(collection, name="2024_12")
```

### Best Practices

| Recommendation | Guideline | Reason |
|----------------|-----------|--------|
| **Partition Size** | 20K-100K rows each | Ensures proper indexing (min 1,024 rows) |
| **Max Partitions** | 1,024 per collection | Milvus hard limit |
| **Data per Partition** | <1B entities | Performance optimization |
| **Naming Convention** | `YYYY_MM` or `YYYY_MM_DD` | Clear time-based organization |

### Querying with Partitions

```python
# Search only in recent partitions (faster)
results = collection.search(
    data=[query_embedding],
    anns_field="embedding",
    param={"metric_type": "COSINE", "params": {"ef": 100}},
    limit=10,
    partition_names=["2024_11", "2024_12"]  # Only search last 2 months
)
```

**Performance Gain**: Searching 2 partitions instead of 12 = ~6x faster queries

## 4. Distance Metrics

### Metric Types in Milvus

| Metric | Range | Formula | Use Case |
|--------|-------|---------|----------|
| **COSINE** | [-1, 1] | `cos(¸) = A·B / (AB)` | Text embeddings (sentence-transformers) |
| **L2** | [0, ) | `£(Ai - Bi)²` | Image embeddings, spatial data |
| **IP** | [-, ] | `£(Ai × Bi)` | Normalized vectors |

### Cosine Similarity vs L2 Distance

**For Stock RAG with Sentence-Transformers: Use COSINE** 

**Why?**
1. Sentence-transformers (e.g., `all-MiniLM-L6-v2`) are trained with cosine similarity objectives
2. Embeddings are normalized on a hypersphere where **direction matters more than magnitude**
3. L2 distance can misrepresent similarity for normalized vectors

**Example**:
```python
# Two stock news embeddings with similar meaning but different magnitudes
vector_a = [0.8, 0.6, 0.0]  # Normalized length = 1.0
vector_b = [0.4, 0.3, 0.0]  # Normalized length = 0.5

# Cosine similarity = 1.0 (same direction, perfectly similar)
# L2 distance = 0.5 (appears different due to magnitude)
```

**Rule of Thumb**: Match the metric to your embedding model's training objective.
- Sentence-transformers, BERT models ’ **COSINE**
- OpenAI embeddings ’ **COSINE**
- Custom models ’ Check documentation

### Inner Product (IP) Note
If using IP metric, **you must normalize embeddings**:
```python
import numpy as np

# Normalize before insertion
embedding_normalized = embedding / np.linalg.norm(embedding)
```
After normalization: `IP H COSINE`

## 5. Hybrid Search & Metadata Filtering

### What is Hybrid Search?
Combines **vector similarity search** with **metadata filtering** to improve relevance.

**Example Query**: "Find stocks with bullish news from the past week"
1. **Metadata filter**: `date >= today - 7 days AND content_type == 'news'`
2. **Vector search**: Similarity to "bullish sentiment, positive outlook"

### Performance Benefits

- **6.8x performance gain** with BitMap Index on filtered fields
- Reduces search scope before vector comparison
- Improves accuracy by focusing on relevant data

### Implementation

```python
from pymilvus import Collection

collection = Collection("stock_knowledge")

# Define query vector
query_vector = [[0.123, 0.456, ...]]  # 384-dim embedding

# Metadata filter expression
filter_expr = 'symbol == "AAPL" and date >= 1730000000 and content_type == "news"'

# Hybrid search
results = collection.search(
    data=query_vector,
    anns_field="embedding",
    param={"metric_type": "COSINE", "params": {"ef": 100}},
    limit=10,
    expr=filter_expr  # Apply metadata filter before vector search
)
```

### Advanced Filtering (Milvus 2.5+)

**String Matching**:
```python
# Prefix match: stocks starting with "A"
filter_expr = 'symbol like "A%"'

# Contains: news mentioning "earnings"
filter_expr = 'content like "%earnings%"'

# Date range: last 30 days
filter_expr = 'date >= 1730000000 and date <= 1732592000'
```

**JSON Metadata Filtering**:
```python
# Filter by sector in JSON metadata
filter_expr = 'metadata["sector"] == "Technology"'

# Complex multi-condition
filter_expr = 'symbol == "AAPL" and metadata["sector"] == "Technology" and date >= 1730000000'
```

### Best Practices for Stock Filtering

| Use Case | Filter Strategy | Performance Tip |
|----------|----------------|-----------------|
| Recent news | `date >= timestamp` | Use partitions + date filter |
| Specific stocks | `symbol in ["AAPL", "GOOGL"]` | Index symbol field with BitMap |
| Sector analysis | `metadata["sector"] == "Tech"` | Create separate collections per sector |
| Data type | `content_type == "news"` | Use partitions by content type |

## 6. RAG Integration with Milvus

### RAG Workflow

```
User Query ’ Embedding Model ’ Milvus Retrieval ’ Context Ranking ’ LLM Generation ’ Response
```

### Components

1. **Query Embedding**: Convert user question to vector
2. **Retrieval**: Search Milvus for top-k similar documents
3. **Context Assembly**: Gather retrieved text chunks
4. **LLM Generation**: Use context to generate answer

### LangChain Integration

```python
from langchain_milvus import Milvus
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain.chains import RetrievalQA
from langchain_community.llms import Ollama

# Initialize embedding model
embeddings = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2")

# Connect to Milvus
vector_store = Milvus(
    embedding_function=embeddings,
    collection_name="stock_knowledge",
    connection_args={"host": "localhost", "port": "19530"},
)

# Create retriever
retriever = vector_store.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 5, "expr": 'symbol == "AAPL"'}  # Hybrid search
)

# Create RAG chain
llm = Ollama(model="llama3.2")
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=retriever,
    return_source_documents=True
)

# Query
response = qa_chain("What's the recent trend for AAPL?")
print(response["result"])
```

### Query Enhancement Techniques

1. **Hypothetical Document Embeddings (HyDE)**
   - Generate a hypothetical answer, embed it, use for retrieval
   - Better for complex queries

2. **Sub-Queries**
   - Break complex question into smaller queries
   - Example: "Compare AAPL and GOOGL" ’ Query AAPL, Query GOOGL, Compare

3. **Query Expansion**
   - Add synonyms and related terms
   - Example: "stock performance" ’ "stock price, returns, gains, growth"

4. **Step-Back Prompts**
   - Ask broader question first for context
   - Example: "Why did AAPL drop?" ’ "What affects stock prices?" + original query

### Context Optimization

**Problem**: Retrieved chunks may contain noise

**Solutions**:
- **Reranking**: Use cross-encoder to rerank top-k results (k=20 ’ top 5)
- **Context Compression**: Remove irrelevant sentences, keep key information
- **Chunk Size Tuning**: Experiment with 256, 512, 1024 token chunks

```python
from langchain.retrievers import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import CohereRerank

# Add reranker
compressor = CohereRerank(model="rerank-english-v2.0", top_n=5)
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=retriever
)
```

## 7. Embeddings for Financial Data

### Model Comparison

| Model | Dimensions | Training Data | Use Case | Performance |
|-------|-----------|---------------|----------|-------------|
| **all-MiniLM-L6-v2** | 384 | General text | General stock RAG | Fast, good baseline |
| **all-mpnet-base-v2** | 768 | General text | Better accuracy | Slower, higher quality |
| **FinBERT** | 768 | Financial news, SEC filings | Financial sentiment | Domain-specific, best for finance |
| **E5-large-v2** | 1024 | Diverse corpus | High accuracy | Slow, large memory |

### Recommended Strategy

**POC/MVP**: `all-MiniLM-L6-v2`
- Fast inference (~10ms per embedding)
- Small model size (~80MB)
- 384 dimensions = less storage in Milvus
- Good enough for general stock text

**Production (Domain-Specific)**: `FinBERT` or `ProsusAI/finbert`
- Trained on financial corpora
- Understands finance-specific terms (EBITDA, P/E, liquidity)
- Better sentiment analysis for stock news
- 768 dimensions

### Generating Embeddings

```python
from sentence_transformers import SentenceTransformer

# Load model
model = SentenceTransformer('sentence-transformers/all-MiniLM-L6-v2')

# Example stock text chunks
texts = [
    "AAPL reported strong Q4 earnings with EPS of $1.46, beating estimates.",
    "Tesla stock drops 5% after production delays at Gigafactory.",
    "Google announces new AI products at annual developer conference."
]

# Generate embeddings
embeddings = model.encode(texts)
print(embeddings.shape)  # (3, 384)
```

### Text Chunking Strategy for Stock Data

**Price Action Text**:
```
"On 2024-11-15, AAPL closed at $186.40 (+2.3%).
Daily high: $187.20, low: $184.50. Volume: 45.2M shares.
RSI: 62 (neutral), MACD: bullish crossover.
Price above 20-day MA ($182.50) and 50-day MA ($178.30)."
```

**News Article Chunks**:
- Split long articles into 512-token chunks
- Preserve sentence boundaries
- Add metadata: headline, publish date, source

**Fundamental Data Text**:
```
"AAPL Fundamentals (Q4 2024): P/E ratio 28.5, EPS $6.20 (YoY +12%).
Revenue $90.8B (+8% YoY), Net margin 24.3%.
Debt-to-Equity: 1.8, Current ratio: 0.98."
```

### Collection Creation Script

```python
from pymilvus import connections, Collection, CollectionSchema, FieldSchema, DataType

# Connect to Milvus
connections.connect(host="localhost", port="19530")

# Define schema
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="symbol", dtype=DataType.VARCHAR, max_length=10),
    FieldSchema(name="date", dtype=DataType.INT64),
    FieldSchema(name="content", dtype=DataType.VARCHAR, max_length=5000),
    FieldSchema(name="content_type", dtype=DataType.VARCHAR, max_length=50),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=384),
    FieldSchema(name="metadata", dtype=DataType.JSON)
]

schema = CollectionSchema(fields, description="Stock knowledge base")

# Create collection
collection = Collection(name="stock_knowledge", schema=schema)

# Create HNSW index
index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",
    "params": {"M": 16, "efConstruction": 200}
}
collection.create_index(field_name="embedding", index_params=index_params)

# Create partitions for time-based organization
from pymilvus import Partition
for month in ["2024_01", "2024_02", "2024_03", "2024_04", "2024_05", "2024_06",
              "2024_07", "2024_08", "2024_09", "2024_10", "2024_11", "2024_12"]:
    Partition(collection, name=month)

print("Collection 'stock_knowledge' created successfully!")
```

### Data Insertion Script

```python
from sentence_transformers import SentenceTransformer
import time

# Load embedding model
model = SentenceTransformer('all-MiniLM-L6-v2')

# Prepare data
stock_data = [
    {
        "symbol": "AAPL",
        "date": int(time.time()),
        "content": "AAPL shows strong momentum with bullish technical indicators...",
        "content_type": "price_action",
        "metadata": {"sector": "Technology", "price": 186.40}
    },
    # ... more data
]

# Generate embeddings
texts = [item["content"] for item in stock_data]
embeddings = model.encode(texts)

# Prepare insert data
insert_data = [
    [item["symbol"] for item in stock_data],
    [item["date"] for item in stock_data],
    [item["content"] for item in stock_data],
    [item["content_type"] for item in stock_data],
    embeddings.tolist(),
    [item["metadata"] for item in stock_data]
]

# Insert into Milvus
collection.insert(insert_data, partition_name="2024_11")
collection.flush()
print(f"Inserted {len(stock_data)} records into Milvus")
```

## 9. Performance Targets & Optimization

### Target Metrics

| Metric | POC Target | Production Target |
|--------|------------|-------------------|
| **Query Latency** | < 3 seconds | < 500ms |
| **Indexing Time** | ~10 min for 100K docs | ~1 hour for 1M docs |
| **Recall@10** | > 0.85 | > 0.95 |
| **Memory Usage** | < 4GB | < 16GB |
| **Throughput** | 10 QPS | 100+ QPS |

### Optimization Checklist

- [ ] Use HNSW index for datasets >100K
- [ ] Set metric_type to COSINE for sentence-transformers
- [ ] Partition data by time (monthly recommended)
- [ ] Apply metadata filters before vector search
- [ ] Tune HNSW parameters (M=16-32, ef=100-200)
- [ ] Batch insert data (1000-5000 records per batch)
- [ ] Load collection into memory before queries: `collection.load()`
- [ ] Use connection pooling for concurrent queries
- [ ] Monitor index build progress and collection stats

### Common Pitfalls to Avoid

L **Don't**: Use L2 distance with sentence-transformers embeddings
 **Do**: Use COSINE similarity

L **Don't**: Create >1000 partitions
 **Do**: Keep partitions to monthly/quarterly ranges

L **Don't**: Insert single records in a loop
 **Do**: Batch insert 1000+ records at a time

L **Don't**: Search entire collection without filters
 **Do**: Use hybrid search with metadata filters

L **Don't**: Use FLAT index for >100K vectors
 **Do**: Use HNSW or IVF_FLAT for scalability
